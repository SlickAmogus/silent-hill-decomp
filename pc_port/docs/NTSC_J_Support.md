# NTSC-J (Japanese) Support

Implemented 2026-07-10 (commits `4af7db1c7` phase 1, `1ac340612` phase 2),
following the PAL "versions-are-data" model: one executable, runtime region
tables, no `#ifdef` region forks in game code.

## Supported disc

SLPM-86192 **Rev 1 / Rev 2** ("99-06-02" exe, sha1
`499576C15892799826ABC5B1596858A555E2F3B7`, PS-X EXE `t_size 0x13800`).
Rev 1 and Rev 2 share the exe, the file table, and the overlay link base;
they differ only in 13 data files (BODYPROG, B_KONAMI, 9 map overlays,
STF_ROLL, STREAM) — runtime extraction reads whatever the inserted disc has,
so both revs work identically. The **first print (JAP0)** has a different exe
(`1FF53A0F...`), shifted containers (XA bases −1 sector) and its own
`filetable.c.JAP0.inc`; it is detected (exe `t_size` probe) and warned about,
not yet supported.

## Ground truth (probe-verified against the real discs)

- `filetable.c.JAP1.inc` is **index-aligned with USA**: all 2074 entries have
  the same name/path/type at the same index. `Fs_InitFileTableForRegion`
  therefore just memcpys the JAP table (no name-matching pass like EUR).
- XA stream bases = US + 5 sectors (`s_FileXaLoc_JAP`, from the in-tree
  `#else` table). The audio `g_AudioData` sector remap runs for JPN too.
- Map overlays are linked for base **0x800CBBD0** (verified: MAP0_S00's
  message table decodes only at that base) but load at the US 0x800C9578 —
  overlay-internal pointer reads rebase by the delta (player_control.c map
  anim header, lang_text.c message extraction).
- **TIM sweep: all 996 TIMs are shape-identical to US; only 12 differ in
  content** — `TIM/TIPS_E02..15` (11 files) and `TIM/MEMO_INR` — the Japanese
  death-hint / memo images. Same names + shapes, so they load with no code.
  Fonts, title, menus, save/load images: byte-identical to US. The JP retail
  release shipped English UI.
- JP map messages: SJIS strings using the **same `~` control codes as US**
  (`~D ~E ~C ~N ~J(t.t) ~S ~L ~M ~H`, identical grammar). Full-disc alphabet
  scan: only those codes + args + valid JIS X 0208 pairs; no half-width kana.

## Japanese text pipeline

- **Extraction** (`lang_text.c`): per map load, walk the pointer table at
  file offset 0x34 of the loaded overlay (`g_OvlDynamic`) with the JAP base,
  copy strings verbatim (no markup translation), repoint the compiled map
  header (`s_LangMapHeader`). 31 maps are 1:1 with US indices. 14 maps
  differ in count (the US localization split/added lines):
  `lang_jpn_msgmap.inc` carries explicit US→JAP index tables, generated by DP
  alignment of the two tables' `~`-code skeletons (`~J` voice timings are
  language-independent anchors); `-1` = US-only line → compiled English kept
  (~20 lines game-wide, whose content JP merges into the adjacent message).
- **Glyphs** (`pc_kanji.c` + `kanji_font.inc`): retail reads the PSX BIOS
  kanji ROM (`Krom2RawAdd2`) — not shippable. Embedded replacement: the
  **Shinonome 16-dot JIS X 0208 bitmap font** (public domain, Yasuyuki
  Furukawa / efont project; 6879 glyphs; regenerate with
  `tools/make_kanji_font.py` from the `font_src.bit` BDF in
  github.com/code4fukui/shinonome-font).
- **Rendering**: glyphs rasterize on demand into 12×16 4bpp atlas cells in
  the framebuffer margin strips (rows 16..31 and 480..495, x < 320 halfwords;
  CLUT at (256,16)) — the same VRAM band retail JP used; outside both display
  rects (0,32)/(0,256)+224(448i) and the PC framebuffer store paths. The
  16→12 fold ORs neighbouring columns so 1px strokes survive (retail's narrow
  look). Cells never straddle a texture page (21 per page column; 189 total;
  full ⇒ reset). SJIS branches in `Gfx_MapMsg_StringDraw` (SPRT lo-res +
  POLY_FT4 hi-res `~H`), `Gfx_MapMsg_CalculateWidths` (12px per pair), and
  `Gfx_StringDraw` (the `~S` select prompts route Yes/No through it). Atlas
  resets per map load (game_boot.c).
- Fixed on the way: `MSG_COUNT_MAX` 96→176 (MAP7_S02 has 159 US messages —
  the replaced pointer array under-covered MAP4_S01/MAP7_S01/MAP7_S02 on PAL).

## What stays English on JPN (by design / retail-accurate)

Menus, options, inventory item names + descriptions, save/load UI. The JP
retail game shipped these in English too (English UI images + FONT16). The
~20 US-only message lines fall back to English.

## Test checklist (completed — NTSC-J confirmed working in-game)

1. Launcher: Region dropdown shows "NTSC-J (Japan)", Play enabled; or set
   `region = jap` in config.cfg with several bins present.
2. Boot to title (US-identical visuals expected), start New Game.
3. First street message boxes + map-look message: Japanese text, correct
   centering, colors on `~C` spans, select prompt はい/いいえ.
4. Pick up the first-aid kit: Japanese pickup line with the item name inline.
5. A memo (hi-res `~H` path, interlaced): kanji legible at double height.
6. BGM/SFX/voices (XA) play; FMV plays; saves work.
7. Death → TIPS screen shows the Japanese hint image.

## Added 2026-07-10 evening (commits `38bc60ea8`, `9c90980d3`)

- **Title artwork**: retail JP title code is instruction-identical to US
  (structural diff of decrypted overlays: 14/14 functions, 0 opcode diffs);
  the only difference is the file — `TIM/TITLE.TIM` (black bg + scratched
  logo + baked copyright) vs `TITLE_E.TIM`. Both ship on every disc,
  byte-identical, same shape/desc. Runtime Region_JPN branch at the
  GameFs_TitleGfxSeek/Load chokepoint; menu (quote-wrapped START/OPTION),
  fog, and flow were already region-independent.
- **School Mumblers**: JP spawns Mumbler (chara 9) where US spawns Grey
  Child (8) in exactly map1_s00..s03 + map6_s04 (overlay group bytes at
  +0x24C/0x24D; global CHARA_FILE_INFOS byte-identical across discs).
  CharaData_ApplyJpnMapPatches: per-map CLD3<->CLD4 model+texture swap
  (the retail PAL mechanism), applied at map load.
