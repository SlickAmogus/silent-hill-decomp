## Reference correctness pattern (the four pillars)
### groaner (charaId 4) - reference regular enemy
- **Numbers:** HEALTH: base Q12(210.0f); bonus = Rng_Rand16() % Q12(70.0f) (0..70); Normal diff: 1/8 chance health*=2; Hard diff: 1/4 chance health*=2. Recoil-vs-stun threshold = Q12(100.0f) remaining health. health==0 + not targeted -> health=NO_VALUE, collision.state=0 (despawn).
DAMAGE DEALING: melee via func_8008A0E4(1, WEAPON_ATTACK(EquippedWeaponId_HuntingRifle, AttackInputType_Hold), ...), gated by ANIM_TIME_REL_KEYFRAME_IDX_GET(anim.time, 222) < 2u; jump-attack lunge speed MIN(var_v0, Q12(4.5f)).
ANIM TABLE: GROANER_ANIM_INFOS[48] (status range 0..47); s_seeds[48] in groaner_anim_infos.c; GroanerAnimInfos_Init() @ main_pc.c:527-528. status 0xFF = NO_VALUE sentinel. kind: 0=BlendLinear 1=PlaybackOnce 2=PlaybackLoop 3=NULL.
DISPATCH: sharedData_800EEE14_2_s00[10] indexed by controlState, [0]=NULL (init state). sharedData_800EEE3C_2_s00[3]={{0x1000,0x999},{0x6000,0x3000},{0x3000,0x4000}}.
KEYFRAME DATA: ~20 s_Keyframe arrays, PSX VRAM 0x800EEE14..0x800F04C0, from disc_extract/VIN/MAP2_S00.BIN; s_Keyframe = 20 bytes (10x s16 q3_12) identical PSX/PC.
STRUCT OFFSETS (s_SubCharacter, sizeof=296=0x128): model @0x0, position @0x18 (VECTOR3 q19.12), rotation @0x24, fallSpeed @0x34, moveSpeed @0x38, headingAngle @0x3C, flags @0x3E, field_44 @0x44, health @0xB0 (q19_12), damage @0xB4 (s_CharaDamage: position VECTOR3 @+0x0, amount q19_12 @+0xC, total 0x10), collision @0xC8 (s_CharaCollision), properties union @0xE8. e_PropsGroaner: controlState @0xE8. s_CharaCylinder: radius @0x0 (map-geo radius), field_2 @0x2 (chara-to-chara hit radius).
COMBAT GUARD: bodyprog_combat_8008A058.c:1522-1559 one-hit-per-swing bitmask (sp14 & sp10); player target sp10==NO_VALUE(-1).
- **Pattern:** The Groaner is a fully-faithful enemy port. Its correctness rests on FOUR pillars that every enemy must replicate:

1. COMPLETE DATA, NO ZERO-STUBS. Three separate data sources are all real and non-zero:
   - Anim infos: pc_port/src/groaner_anim_infos.c defines `s_AnimInfo GROANER_ANIM_INFOS[48]` (sized exactly to the status enum count, NOT [256]) and a `GroanerAnimInfos_Init()` registered in main_pc.c:527-528. The init is a RUNTIME patch loop because MinGW won't accept cross-TU function symbols (Anim_BlendLinear/PlaybackOnce/PlaybackLoop) as static initializers â€” so the array is zero-init at link and filled at boot from a `s_seeds[48]` table carrying {kind,status,hasVariableDuration,linkStatus,durationConstantQ12,startKeyframeIdx,endKeyframeIdx}. kind 0/1/2 -> Blend/Once/Loop fn-ptr, kind 3 -> NULL playbackFunc.
   - AI dispatch + collision keyframes: src/maps/characters/groaner_rodata.inc holds the real dispatch table `sharedData_800EEE14_2_s00[10]` (indexed by controlState, entry [0]=NULL is the init state handled by Ai_Groaner_Init), the sound-query table `sharedData_800EEE3C_2_s00[3]`, and ~20 `s_Keyframe[]` collision arrays extracted from disc (MAP2_S00.BIN @ PSX VRAM 0x800EEE14..0x800F04C0). s_Keyframe is 20 bytes on PSX and PC so arrays drop in with no reformat.
   - CRITICAL DLL RULE: groaner_rodata.inc is `#include`d at the BOTTOM of groaner.c (inside #ifdef SH_PC_PORT), NOT compiled into the exe, because the dispatch table points at sharedFunc_800Exxxx functions that are DLL-internal; the exe import lib can't see them, so the table must live in the SAME translation unit. The anim-info table, by contrast, lives in the exe (shared via import lib) since its fn-ptrs are exe-resident.

2. LIVE REGISTRATION via per-map header charaUpdateFuncs. Groaner_Update is wired into each hosting map's `.charaUpdateFuncs[]` at the Chara_Groaner slot (e.g. map2_s00_header.c:164-165, map2_s02/map4_s02/map5_s01/map6_s00). groaner.c is compiled LIVE per map (it's #included via the rodata pattern in each map DLL). Signature: `void Groaner_Update(s_SubCharacter* groaner, s_AnmHeader* anmHdr, GsCOORDINATE2* coords)`.

3. ONCE-PER-SWING, FPS-SAFE DAMAGE DEALING. Groaner deals damage by calling the shared melee primitive `func_8008A0E4(1, WEAPON_ATTACK(EquippedWeaponId_HuntingRifle, AttackInputType_Hold), groaner, &pos, &player, rot, Q12_ANGLE(90.0f))` gated by `ANIM_TIME_REL_KEYFRAME_IDX_GET(anim.time, 222) < 2u` â€” a RANGE window relative to a keyframe, never `== exactKf`. func_8008A0E4/func_8008A058 itself carries the SH_PC_PORT one-hit-per-swing guard (bodyprog_combat_8008A058.c:1522-1559): a per-swing already-hit bitmask `(sp14 & sp10)` zeroes damageAmount+knockback on repeat frames (PSX applied unconditionally because its 2-frame hitbox window read as a single hit; on PC the window spans the whole swing). For the player target sp10==NO_VALUE(-1) so `(sp14 & sp10)==sp14` latches the hit. Chainsaw/RockDrill are explicitly exempt (continuous weapons). Damage is then applied via `target->damage.amount += damageAmount` exactly once.

4. REAL FLOOR/COLLISION FROM DATA, AIRBORNE TRACKING. Movement+floor handled in sharedFunc_800E5AA4_2_s00: applies g_GravitySpeed to fallSpeed (halved during JumpAttack), calls `func_8005CB20(groaner, &collResult, field_F0, field_F2)` to resolve motion+floor, then sets/clears GroanerFlag_Airborne by comparing `position.vy == collResult.surface.groundHeight`. Per-keyframe hit/collision shapes come from the extracted s_Keyframe data via `Collision_CharaCollisionSet(groaner, &kf0, &kf1)` and the CopyData macro (radius = real field data, NOT a hardcoded PC fallback), followed by `Chara_CollisionShapeOffsetsUpdate`.

DAMAGE-TAKING is data-driven and correct: health initialized in Ai_Groaner_Init = `Q12(210.0f) + (Rng_Rand16() % Q12(70.0f))` (base 210, up to +70 bonus), with difficulty multipliers (Normal 1-in-8 chance x2, Hard 1-in-4 chance x2). On hit, sharedFunc_800E33DC_2_s00 does `health = MAX(health - damage.amount, Q12(0.0f))`, picks recoil vs stun by remaining health thresholds (>100 = stand-recoil, <=100 = stun-to-death path), then `Chara_DamageClear`. Death: when health hits 0 and not airborne, transitions to a death anim and controlState GroanerControl_Death; when health==0 and no longer the targeted NPC, health=NO_VALUE and collision.state=0 (despawn). controlState==0 sentinel triggers one-time Ai_Groaner_Init.

ALL movement/rotation/timer arithmetic is g_DeltaTime / TIMESTEP_ANGLE / Q12_MULT_PRECISE based (frame-rate independent), and the whole update is gated `if (g_DeltaTime != Q12(0.0f))` so it freezes cleanly on pause. The only SH_PC_PORT additions inside groaner.c are: a cached getIndex() (MIPS eval-order safety), NULL-guards on the dispatch entry-0 call, and diagnostic logging â€” i.e. the game logic is otherwise untouched clean decomp.

### floatstinger (15) - reference BOSS
- **Numbers:** Health: Q12(4000) normal/easy, Q12(6000) Hard. Per-frame damage intake cap field_108: Q12(300) normal, Q12(500) easy. Phase/stagger thresholds: field_F8 > 1000 (-> stagger controlState 3), field_FA > 1200 (-> stagger + FloatstingerFlag_1 enrage). Anim table: FLOATSTINGER_ANIM_INFOS[28]; idle hover = FloatstingerAnim_9 (status ANIM_STATUS(9,true)), kf 191..222 loop; charge attack = FloatstingerAnim_1 kf 1..31; dive/spit = FloatstingerAnim_12 kf 1..31. Charge anim duration set per-difficulty: Q12(26) easy / Q12(32) normal / Q12(38) Hard. Attack windows: Anim_1 melee fires func_8008A0E4 during anim.time 17..25; Anim_12 projectile fires after time>=18. Knockback gate: shared sp14 & sp10 once-per-swing bitmask (bodyprog_combat_8008A058.c ~L1545-1558). Collision cylinder radius Q12(0.4) or Q12(0.5) recomputed each frame from GTE-projected anchors; box.bottom Q12(-1.46) (alive) / Q12(-2.0) (player dead). Control-state dispatch D_800D7A04[7]: {NULL, NULL, func_800D1BF8, func_800D2B90, func_800D341C, func_800D3424, func_800D3564}. Death: controlState FloatstingerControl_6, EventFlag_350. Damage-rate constant D_800D785C: Q12(2.4) Hard / Q12(3.2) normal / Q12(4.0) easy. attack weapon id = EquippedWeaponId_Unk59.
- **Pattern:** A boss is structurally a CHARACTER with a BIG health pool plus its own multi-handler control-state machine, but it reuses the SAME shared infrastructure as regular enemies: real extracted anim infos (FLOATSTINGER_ANIM_INFOS[28] + FloatstingerAnimInfos_Init registered in main_pc.c), an extracted AI dispatch table (D_800D7A04 in floatstinger_rodata.inc, included at bottom of floatstinger.c so the map DLL gets it), the shared damage/knockback emitter func_8008A0E4, and the shared one-hit-per-swing guard in bodyprog_combat_8008A058.c. It is LIVE via #include "../src/maps/characters/floatstinger.c" in map4_s05.c and registered as Floatstinger_Update in map4_s05_header.c charaUpdateFuncs[].

KEY BOSS-SPECIFIC TRAITS vs a regular enemy:
1. HEALTH: huge and difficulty-scaled. Floatstinger_Init sets health = Q12(4000) normal/easy, Q12(6000) on Hard (vs regular enemies ~tens-hundreds). Health is NEVER reduced directly by the shared combat code; instead func_800D1968 reads floatstinger->damage.amount each frame, caps how much damage a single accumulation can contribute (field_108 capped at Q12(300) normal / Q12(500) easy â€” a damage-rate limiter so the boss cannot be bursted down), subtracts into health, clears damage via Chara_DamageClear, and plays a hurt SFX. Player_DisableDamage is used so health clamps to 1 (not 0) while the player is mid-action, then to 0 to allow death.

2. DAMAGE-DRIVEN PHASE/STAGGER STATE MACHINE: accumulated damage thresholds (field_F8 > 1000, field_FA > 1200) flip controlState from FloatstingerControl_2 (normal hover/attack) to FloatstingerControl_3 (stagger/recoil), and field_FA>1200 additionally sets FloatstingerFlag_1 (enraged-stagger variant). This is the "multi-phase" mechanism â€” phases are gated on cumulative damage, not a single HP bar split. Death sets controlState to FloatstingerControl_6 and sets EventFlag_350.

3. CONTROL-STATE DISPATCH: Floatstinger_ControlUpdate calls D_800D7A04[controlState](floatstinger). Handlers: [2]=func_800D1BF8 (main hover + dive/spit attacks), [3]=func_800D2B90 (stagger + procedural wing-stroke), [5]=func_800D3424 (appear/intro), [6]=func_800D3564 (death). Indices 0,1 are NULL. PC-port note: PSX passed the chara implicitly in a0; the PC table is typed (s_SubCharacter*) and the call site passes it explicitly.

4. ATTACK / KNOCKBACK: two attacks, both gated on anim.time windows (NOT exact keyframes). FloatstingerAnim_1 (charge/swoop) fires func_8008A0E4 once during time window 17..25 with WEAPON_ATTACK(EquippedWeaponId_Unk59, AttackInputType_Tap), passing GTE-transformed wing-tip world positions sp20[0]/[1] as the hit origin and two ratan2 angles for knockback direction. FloatstingerAnim_12 (dive/projectile spit) fires sharedFunc_800CB0A4_4_s03 to launch projectiles (more on Hard via FloatstingerFlag_0, spawning 2 extra spread shots). Knockback magnitude/direction flows through func_8008A0E4 -> var_s7 applied to target->damage.position, and is rate-limited to ONCE PER SWING by the shared sp14 & sp10 bitmask guard. The reason air_screamer 'shoves but barely damages' is the inverse of this working pattern: its attack must register damageAmount > 0 through func_8008A0E4 (real weapon-attack table entry) AND its knockback must be gated once-per-swing â€” if damage is zero/missing the player only gets the knockback (shove) with no health loss, and without the once-per-swing guard high FPS multiplies the shove every frame.

5. COLLISION/HIT SIZING is fully data/GTE-driven per frame: func_800D3AD4 recomputes the boss's box top/height/offsetY and cylinder radius (Q12(0.4)/Q12(0.5)) from three GTE-projected body anchor points (D_800DB928 hierarchy via Vw_CoordHierarchyMatrixCompute + gte_rt), and shrinks the cylinder during the charge anim's time window â€” the hit radius is never a hardcoded PC fallback. This is the contrast to broken enemies using a hardcoded radius.

6. FLOOR/FALL handling: func_800D35F0 moves via Collision_WallDetect + a custom floor-clamp func_800D4458 (3 floor boxes D_800D780C) and clamps vy to floor; func_800D4A3C drives approach/fall toward the player with clamped fallSpeed â€” the boss is a flyer so it manages its own vertical clamp rather than relying on generic chara gravity.

7. PROCEDURAL ANIMATION: wings are driven two ways â€” keyframe playback (anim.status loops) AND a procedural wing-stroke in func_800D2B90/func_800D37E8 writing D_800DB8A8[15] from phase D_800D7858, applied to bone matrices via Math_RotMatrixZxyNegGte/MulMatrix. PC-port fix: D_800D799C is an ALIAS into FLOATSTINGER_ANIM_INFOS[idle].duration.constant (the game writes wing-flap speed through this every frame); a zero-stub disconnect froze the idle wings.

8. DRAW/OT: per-frame draw markers (func_800D3F84) clamp into a fixed OT bucket (g_OrderingTable0[idx].org[12]) and only emit when sp48.vz >= GeomScreen distance â€” PC adds an extra (sp48.vz > 0) guard to keep x86 idiv from dividing by zero. No unbounded otz-derived OT index.

HIGH-FPS CORRECTNESS: every timing gate uses anim.time RANGE windows (e.g. time>17 && time<25, time>0 && time<18) and g_DeltaTime-scaled accumulators, NOT '== exactKeyframe' or raw frame counts. The damage/knockback emit is once-per-swing via the shared bitmask. This is why it works at uncapped FPS.
